1. Resumen Ejecutivo

El proyecto Pedidos360 es una plataforma web cloud native diseñada bajo una arquitectura desacoplada de microservicios, orientada a la alta disponibilidad, seguridad y mantenibilidad en la nube de Amazon Web Services (AWS).

A la fecha, el proyecto cuenta con su infraestructura base en AWS operativa en la región us-east-1, con despliegue verificado en Amazon EC2 mediante servicios systemd, persistencia relacional implementada mediante Spring Data JPA para PostgreSQL, y planes exhaustivos de integración para Amazon RDS y AWS API Gateway.

Hitos Clave Completados:
  • EC2 Desplegado y Activo: Microservicios ejecutándose con Amazon Corretto 21 bajo systemd (BFF en 0.0.0.0:8080, Pedidos en 127.0.0.1:8081 y Productos en 127.0.0.1:8082).
  • Persistencia JPA Completa: CRUDs de Productos y Pedidos con entidades, DTOs, validaciones con Jakarta Validation y manejo global de excepciones en JSON.
  • Aislamiento y Seguridad: Cero secretos en repositorios Git, comunicación inter-servicios restringida a loopback local y pruebas automatizadas 100% aisladas con H2.
  • Control de Versiones: Repositorio Git limpio, estructurado y versionado con commits descriptivos bajo estándar Conventional Commits.

2. Arquitectura del Sistema

La arquitectura global sigue el patrón Backend For Frontend (BFF), donde el cliente web no consume directamente los microservicios de dominio ni la base de datos, sino que interactúa con un API Gateway público que enruta el tráfico hacia el BFF.

3. Microservicios Backend y Persistencia JPA

3.1 BFF Service (bff-service)

  • Puerto: 8080 (escucha en 0.0.0.0:8080).
  • Rol: Puerta de enlace interna hacia los microservicios de dominio. Orquesta peticiones y centralizará la validación de tokens JWT en etapas posteriores.
  • Aislamiento de BD: No contiene configuración ni dependencias directas de JPA/PostgreSQL.
  • Health Checks: GET /api/health y GET /actuator/health respondiendo HTTP 200 UP.

3.2 Productos Service (productos-service)

  • Puerto: 8082 (escucha en 127.0.0.1:8082, no expuesto públicamente).
  • Entidad Producto: Campos id (Long), nombre (String), descripcion (String), precio (BigDecimal), stock (Integer), activo (Boolean), createdAt y updatedAt.
  • Operaciones CRUD implementadas:
    MétodoEndpointRespuesta ExitosaDescripción
    POST/api/productos201 CreatedCrea un nuevo producto validado.
    GET/api/productos200 OKLista productos (activos por defecto o todos).
    GET/api/productos/{id}200 OKBusca un producto por su ID (404 si no existe).
    PUT/api/productos/{id}200 OKActualiza datos de un producto existente.
    DELETE/api/productos/{id}204 No ContentEliminación lógica del producto (activo=false).

3.3 Pedidos Service (pedidos-service)

  • Puerto: 8081 (escucha en 127.0.0.1:8081, no expuesto públicamente).
  • Entidad Pedido: Campos id (Long), usuario (String), fecha (LocalDateTime), estado (Enum EstadoPedido: PENDIENTE, CONFIRMADO, EN_PROCESO, COMPLETADO, CANCELADO persistido como STRING), total (BigDecimal), createdAt y updatedAt.
  • Operaciones CRUD implementadas:
    MétodoEndpointRespuesta ExitosaDescripción
    POST/api/pedidos201 CreatedRegistra un nuevo pedido.
    GET/api/pedidos200 OKLista todos los pedidos registrados.
    GET/api/pedidos/{id}200 OKBusca un pedido por ID (404 si no existe).
    GET/api/pedidos/usuario/{usuario}200 OKFiltra pedidos por usuario/cliente.
    PUT/api/pedidos/{id}200 OKActualiza estado o monto del pedido.
    DELETE/api/pedidos/{id}204 No ContentElimina el registro de pedido.

6. Próximos Pasos (Hoja de Ruta Final)

  1. Microsoft Entra ID (Azure AD): Registro de aplicación frontend (Single Page App) y backend API con scopes y roles.
  2. Angular + MSAL: Integración de @azure/msal-angular y @azure/msal-browser con MsalGuard e interceptor Bearer Token.
  3. Seguridad JWT en BFF: Configuración de Spring Security OAuth2 Resource Server para validación de firma, issuer y audiencia con JWKS de Microsoft.
  4. AWS API Gateway: Aprovisionamiento de HTTP API pedidos360-api con enrutamiento proxy y CORS para http://localhost:4200.
  5. Frontend Hosting en AWS: Despliegue de Angular en Amazon S3 + Amazon CloudFront con CDN y HTTPS.
  6. Presentación y Demo en Vivo: Demostración de flujos 200 / 201 / 204 / 400 / 401 / 403 / 404 y persistencia en RDS.
Conclusión: El proyecto se encuentra en un estado óptimo, con arquitectura desacoplada, código limpio, pruebas pasando en su totalidad y listo para la fase de autenticación federada y hosting web.
